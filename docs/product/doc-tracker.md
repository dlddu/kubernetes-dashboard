## 위험 진단

### 고아 가치 (소유자 없는 가치)
- (없음) — 모든 가치가 "클러스터 운영자"를 소유자로 가진다.

### 미정렬 문서 (가치 참조 없는 문서)
- (없음) — 9개 PRD 모두 하나 이상의 가치를 참조한다.

### 무가치 PRD (가치를 달성하지 않는 PRD)
- (없음)

### AC 없는 PRD
- (없음) — 모든 PRD가 AC를 포함한다.

### 미연결 AC (가치와 연결되지 않은 AC) 🟡
- **SC3 (Secrets 삭제)** — 정의된 V1~V7 중 "민감 리소스 관리/삭제" 또는 "파괴적 작업의 안전장치"를 다루는 가치가 없어 연결 불가.
  - 조치: ① 가치 추가 후 연결(이전에 보류한 "안전장치" 가치가 후보), 또는 ② SC3을 범위에서 제외.

### 미검증 AC (테스트 없는 AC) 🟢
- **전체 49개 AC** — Phase 3 테스트 문서 미작성.
- 참고: 대부분의 AC는 코드베이스에 대응 e2e 스펙이 존재한다(각 PRD의 "검증 방법" 참조). AC↔테스트를 명시적으로 잇는 테스트 문서만 없는 상태다. 대응 e2e가 없어 새로 작성이 필요한 대표 공백: OV1·OV5·OV7, SC2·SC3·SC4 등.

### 고아 테스트 (AC를 참조하지 않는 테스트)
- (없음) — 테스트 문서 미작성

## 다음 단계 제안

우선순위(계층 상위부터):

1. 🟡 **SC3 미연결 해소** — "안전장치/민감 리소스 관리" 가치를 추가하거나 SC3을 범위에서 제외.
2. 🟢 **테스트 문서(Phase 3)** — PRD의 AC를 기존 e2e 스펙에 연결하는 테스트 문서 작성. 우선순위 높은 영역: Pods(PD) → Overview(OV) → 공통 셸(CM) → FluxCD(FX).
3. (선택) **디버그 모드 PRD** — `DebugToggle`/`/debug`는 현재 어느 PRD에도 없다. 개발자 진단용이라 가치 매핑이 모호하므로 가치 추가 여부와 함께 검토.
